# CIEL Cloudflare build recovery — 2026-11-02

## Root cause 1: missing generated entrypoint

Cloudflare Workers Builds runs bun install, then the configured deploy/preview command. The Wrangler entrypoint is generated by scripts/reassemble-recovered-worker.mjs and then patched by scripts/apply-paper-tier-fix.mjs; neither generated file is checked in because reconstructed/ is intentionally git-ignored.

## Fix 1: build bootstrap

- npm run build reconstructs the deployed bundle, applies the deterministic CIEL patch, checks syntax, runs paper sizing tests and validates the staging Wrangler config.
- The staging wrangler.jsonc points to reconstructed/patched-worker.js, the file produced by the build.
- The root postinstall: npm run build hook is executed by the Bun install step shown in the Cloudflare log. It creates the Wrangler entrypoint before Workers Builds invokes Wrangler.
- GitLab CI also runs a Bun 1.4.4 bootstrap job against the same install lifecycle.

## Root cause 2: Workers Builds is running Preview, not Deploy

The latest Cloudflare build log confirms the configured command is npx wrangler preview, not npx wrangler deploy. This is expected for a non-production branch when Workers Builds Preview builds are enabled. Worker Previews require a top-level previews block; top-level vars and bindings are not inherited by Previews.

## Fix 2: explicit isolated Preview configuration

The Wrangler config now defines Preview variables, D1 and KV bindings explicitly. Preview D1/KV point to the same new-account staging-only resources as the staging Worker. This is a shared staging dataset for branch Previews; it does not point to the original production account. Durable Object Preview namespaces are provisioned separately by Cloudflare. Cron triggers are intentionally omitted from Preview settings.

The staging D1/KV IDs remain placeholders until the new-account resources are provisioned. The build check verifies that both the deployment and Preview bindings use those placeholders and that neither source-account resource ID appears. Do not replace them with production IDs.

Wrangler 4.135.0 or later is required for Worker Previews; the repository now declares that minimum version.

## Remaining provisioning requirements

Before a Preview can run with working state:
1. Create the staging D1 database and KV namespace in the connected staging account.
2. Replace the two placeholder IDs in both top-level and previews bindings (the values must match).
3. Apply the recovered D1 schema to the staging database.
4. Configure Preview secrets separately in Cloudflare; secret plaintext is never committed.
5. Confirm the connected Worker name and account are the intended staging target before allowing the first remote Preview.

The source Worker and its production resources remain untouched. Do not merge or deploy to the original source account. The new-account Cloudflare connection was not accessed or changed as part of this repository fix.
